# Plan v0.1.0 — First sync

Goal: a reading session on the Kindle ends up in Postgres, and the web dashboard shows the number of books read.

End-to-end flow:

```
Kindle (plugin) --pairing--> API <--session cookie-- Web (sign up, /link, dashboard)
Kindle (plugin) --POST /v1/ingest (Bearer device token)--> API --> Postgres
```

Out of scope: community features, public profiles, SEO pages, admin back-office, book metadata enrichment, highlights sync.

## 0. Decisions to validate at session start

### When to sync (plugin)

KOReader's statistics plugin buffers page data in memory and flushes it to `statistics.sqlite3` on document close, on suspend and periodically. The plugin reads the database, never the in-memory buffer.

| Trigger                | Action                                                                                                                        | Default          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| `onCloseDocument`      | Sync if online.                                                                                                               | on               |
| `onResume`             | Sync if online (Wi-Fi may need a few seconds: use `NetworkMgr:runWhenOnline`/`willRerunWhenOnline` without forcing Wi-Fi on). | on               |
| `onNetworkConnected`   | Sync pending data.                                                                                                            | on               |
| Periodic while reading | Every N minutes (setting: off / 15 / 30 / 60).                                                                                | 30               |
| Manual                 | Menu entry "Sync now" (may turn Wi-Fi on, with user prompt).                                                                  | always available |
| `onSuspend`            | No network (Wi-Fi goes down). Nothing to do.                                                                                  | —                |

Guards:

- Throttle: at most one automatic sync every 5 minutes (manual sync bypasses it).
- Never turn Wi-Fi on automatically (battery). Setting: "Allow turning Wi-Fi on for sync" (default off).
- Nothing to send (cursor up to date): no ingest request, only a device status check (detects a revoke from the website).
- Failure: keep cursor, retry on next trigger. No retry loop.

### Auth (web)

Better Auth, email + password, cookie session on the API domain. No 2FA for now. Email verification later.

## 1. Database schema (`packages/db`)

Tables (Drizzle, `snake_case`):

- Better Auth tables: `user`, `session`, `account`, `verification`.
- `devices`: `id`, `user_id`, `name`, `model`, `token_hash` (sha256, unique), `last_sync_at`, `created_at`, `revoked_at`.
- `device_pairings`: `id`, `device_code_hash` (unique), `user_code` (unique, 8 chars, unambiguous alphabet), `device_name`, `device_model`, `user_id` (null until confirmed), `expires_at` (+10 min), `consumed_at`.
- `books`: `id`, `user_id`, `md5` (KOReader partial md5), `title`, `authors`, `series`, `language`, `pages`, `notes`, `highlights`, `last_open`, `total_read_time`, `total_read_pages`, `created_at`, `updated_at`. Unique `(user_id, md5)`. Every column of KOReader's `book` table is kept.
- `page_stats`: `user_id`, `book_id`, `page`, `start_time` (timestamptz), `duration` (s), `total_pages`. Primary key `(book_id, page, start_time)`: idempotent upsert.

Deliverables: schema, first migration, `pnpm --filter @koreader-dashboard/db db:migrate` documented, tables visible in Adminer.

## 2. API (`apps/api`)

- Wire `createDb(env.DATABASE_URL)`, error handler, JSON 404.
- `@hono/zod-openapi`: routes declared with Zod schemas, spec served at `/openapi.json`.
- Better Auth mounted on `/v1/auth/*`.
- Pairing:
  - `POST /v1/devices/pair/start` `{ device_name, device_model }` -> `{ device_code, user_code, verification_url, expires_in, interval }`.
  - `POST /v1/devices/pair/confirm` (session) `{ user_code }` -> 204. Rate limited.
  - `POST /v1/devices/pair/poll` `{ device_code }` -> `428 authorization_pending` | `410 expired` | `200 { device_token }` (one shot).
  - `GET /v1/devices` (session), `DELETE /v1/devices/:id` (session, revoke).
- Device auth middleware: `Authorization: Bearer <token>`, lookup by `sha256(token)`, reject revoked. Updates `last_sync_at`.
- `POST /v1/ingest` (device token):
  - Body: `{ books: [{ md5, title, authors, series, language, pages }], page_stats: [{ md5, page, start_time, duration, total_pages }] }`.
  - Limits: max 5,000 `page_stats` per request; plugin batches.
  - Upsert books, then `INSERT ... ON CONFLICT DO NOTHING` page stats, in one transaction.
  - Response: `{ accepted, cursor }` where `cursor` is the max `start_time` stored.
- `GET /v1/me/summary` (session): `{ books_count, total_read_seconds, total_pages_read }`.

Deliverables: endpoints, a few targeted tests (Vitest) on pairing and ingest idempotency.

## 3. Plugin (`apps/koplugin`)

Files (submodules under `kodashboard/` to avoid `require` name clashes with other plugins): `main.lua` (events, menu), `settings.lua` (`LuaSettings` in `settings/koreader-dashboard-ulysse.lua`), `stats.lua` (SQLite reads), `api.lua` (HTTP + JSON), `pairing.lua` (UI).

- Settings: `server_url` (default production URL, editable for local dev: `http://<mac-ip>:8787`), `device_token`, `cursor` (last synced `start_time`), sync options from section 0.
- `stats.lua`: open `DataStorage:getSettingsDir() .. "/statistics.sqlite3"` read-only with `lua-ljsqlite3`; select `page_stat_data` rows with `start_time > cursor` joined to `book`, ordered by `start_time`, batch of 5,000.
- `api.lua`: `socket.http`/`ssl.https` through `socketutil` timeouts, `json` encode/decode, `Authorization` header. Handle `401` (token revoked: clear token, notify user).
- `pairing.lua`: menu "Link this device" -> start -> show `user_code` and QR (`QRMessage`) with `verification_url` -> poll every `interval` until token or expiry -> save token. Menu "Unlink device".
- Menu: Link/Unlink, Sync now, Last sync (time + rows sent), Sync settings, Server URL, About.
- Sync triggers and guards from section 0.

Deliverables: plugin tested on the Kindle Paperwhite 2024 (KOReader 2026.07.1) over USB, `crash.log` clean, rows visible in Adminer.

## 4. Web (`apps/web`)

- API client (`fetch` wrapper, `credentials: 'include'`, base URL from `NEXT_PUBLIC_API_URL`).
- Pages: `/sign-up`, `/sign-in`, `/link` (enter code, supports `?code=`), `/dashboard`.
- `/dashboard`: cards "Books", "Total reading time", "Pages read" from `/v1/me/summary`, skeleton loaders, mobile-first.
- `/dashboard/devices`: list and revoke devices.
- Landing page stays minimal.
